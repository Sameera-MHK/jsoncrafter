## Why

Frontend work often starts from a JSON sample: an API response, a fixture, a backend teammate's example payload. Writing the matching TypeScript interfaces and Zod schemas by hand is slow and drifts out of sync, and you usually also want a quick local API that serves the same JSON while the real backend is not ready.

`jsonforge` does those three things with one small tool:

- `jsonforge types` — TypeScript interfaces
- `jsonforge zod` — Zod schemas with inferred types
- `jsonforge generate` — both
- `jsonforge mock` — a read-only local REST API from JSON fixtures

TypeScript and Zod output come from the same inference model, so they always agree on the same input. Generation runs fully offline for local files. The package has no runtime dependencies.

## Installation

Requires **Node.js 22 or newer**.

```bash
# As a dev dependency (recommended)
npm install --save-dev jsonforge-cli

# Or globally
npm install --global jsonforge-cli

# Or without installing
npx jsonforge-cli --help
```

The generated Zod files import `zod`, so install it in the project that uses them:

```bash
npm install zod
```

## Quick start

```bash
jsonforge types user.json                 # -> user.types.ts
jsonforge zod user.json                   # -> user.schema.ts
jsonforge generate user.json              # -> user.types.ts + user.schema.ts
jsonforge mock ./fixtures                 # -> http://127.0.0.1:4000
```

Output files are written next to the input file. Existing files are never overwritten unless you pass `--force`.

## JSON to TypeScript

Given `user.json`:

```json
{
  "id": 1,
  "name": "Ada Lovelace",
  "profile": { "bio": "Mathematician", "website": null },
  "roles": ["admin"]
}
```

```bash
jsonforge types user.json --name User --output src/types/user.ts
```

prints a warning for `website` (only `null` was seen, see [Known limitations](#known-limitations)) and produces:

```ts
// Generated by jsonforge-cli from user.json.

export interface User {
  id: number;
  name: string;
  profile: Profile;
  roles: string[];
}

export interface Profile {
  bio: string;
  website: null;
}
```

```ts
import type { User } from "./types/user";
```

### Arrays and multiple samples

A top-level array is treated as a list of samples. All items are merged into one item type:

- a key missing from some items becomes optional (`nickname?: string`)
- a key with different value types becomes a union (`id: string | number`)
- `null` mixed with another type becomes nullable (`zip: string | null`)

```json
[
  { "id": 1, "name": "Ada", "zip": null },
  { "id": "2", "name": "Alan", "zip": "M1", "nickname": "Prof" }
]
```

```ts
export type Users = User[];

export interface User {
  id: string | number;
  name: string;
  zip: string | null;
  nickname?: string;
}
```

(Unions are always printed in a fixed order: `string`, `number`, `boolean`, object, array, `unknown`, `null`.)

### Naming rules

- The root type name comes from `--name`, otherwise from the file name (`user-profile.json` → `UserProfile`), the last URL path segment, or `Root` for stdin.
- Nested object types are named after their property in PascalCase (`shipping_address` → `ShippingAddress`).
- Array item types use a simple singular form (`users` → `User`, `categories` → `Category`). If that gives the same name, `Item` is appended (`status` → `StatusItem`).
- Name collisions get a number (`Item`, `Item2`).
- Names that clash with reserved words or common built-in types get a `Type` suffix (`object` → `ObjectType`, `string` → `StringType`).
- Property names that are not valid identifiers are quoted (`"first-name": string`).

## JSON to Zod

```bash
jsonforge zod user.json --name User --output src/schemas/user.schema.ts
```

```ts
// Generated by jsonforge-cli from user.json.

import { z } from "zod";

export const ProfileSchema = z.object({
  bio: z.string(),
  website: z.null(),
});
export type Profile = z.infer<typeof ProfileSchema>;

export const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  profile: ProfileSchema,
  roles: z.array(z.string()),
});
export type User = z.infer<typeof UserSchema>;
```

```ts
import { UserSchema, type User } from "./schemas/user.schema";

const user: User = UserSchema.parse(await response.json());
```

Every schema is exported along with its inferred type. Schemas are declared before they are used, so the file works without `z.lazy`.

**Zod version:** output targets **Zod 4** and is tested against Zod 4.6. It only uses `z.object`, `z.array`, `z.union`, `z.record(z.string(), …)`, `.nullable()` and `.optional()`, which also exist in Zod 3, but Zod 3 is not tested.

## Generate both

```bash
jsonforge generate user.json                       # next to user.json
jsonforge generate user.json --output src/generated
# -> src/generated/user.types.ts
# -> src/generated/user.schema.ts
```

For `generate`, `--output` is a **directory**. Before writing, every target is checked, so nothing is written if any file already exists (without `--force`).

## Mock REST API

```bash
jsonforge mock ./fixtures --port 4000
```

```
Mock server running at http://127.0.0.1:4000

  GET http://127.0.0.1:4000/api/posts  <- fixtures/api/posts.json
  GET http://127.0.0.1:4000/users  <- fixtures/users.json

Press Ctrl+C to stop.
```

### Route mapping

| File | Route |
| --- | --- |
| `fixtures/users.json` | `GET /users` |
| `fixtures/api/posts.json` | `GET /api/posts` |
| `fixtures/index.json` | `GET /` |
| `fixtures/api/index.json` | `GET /api` |

- You can pass a single `.json` file instead of a directory.
- Trailing slashes and query strings are ignored (`/users/?page=2` → `/users`).
- If there is no `index.json`, `GET /` returns `{ "routes": [...] }`.
- Unknown routes return `404` with `{ "error": "Not found", "path": "..." }`.
- Only `GET` and `HEAD` are supported; other methods return `405`.
- Files and folders starting with `.` and symbolic links are skipped.
- Fixtures are read once at startup. Restart the server after editing them.
- Responses include `Access-Control-Allow-Origin: *` so a frontend dev server on another port can call the API.

### Delays and error responses

```bash
jsonforge mock ./fixtures --delay 500          # every response waits 500 ms
curl "http://127.0.0.1:4000/users?_status=500" # -> 500 {"error":"Internal Server Error","status":500}
```

`_status` accepts any value from 400 to 599.

### Using it from a frontend

```js
// Next.js / Vite / CRA
const res = await fetch("http://127.0.0.1:4000/users");
const users = await res.json();
```

Use `--port 0` to pick a random free port.

## URL and stdin input

```bash
# URL (http and https only)
jsonforge types https://api.example.com/v1/users --name User

# Authenticated APIs (repeat -H for more headers)
jsonforge zod https://api.example.com/v1/me -H "Authorization: Bearer $TOKEN"

# stdin
cat user.json | jsonforge types - --name User
curl -s https://api.example.com/v1/users | jsonforge generate - --name User --output src/generated
```

- With a URL or stdin and no `--output`, files are written to the current directory, named from the type name (`--name UserProfile` → `user-profile.types.ts`).
- Responses must have a JSON content type (`application/json` or `application/*+json`), be at most 5 MB, and arrive within the timeout (`--timeout`, default 10000 ms).
- Up to 5 redirects are followed. Headers are dropped when a redirect goes to a different origin.

### Shell quoting

- macOS/Linux shells: quote headers with double quotes so `$TOKEN` is expanded: `-H "Authorization: Bearer $TOKEN"`. Quote URLs that contain `?` or `&`.
- Windows PowerShell: use `-H "Authorization: Bearer $env:TOKEN"`, and pipe files with `Get-Content user.json -Raw | jsonforge types -`.
- Windows cmd.exe: use double quotes only; single quotes are not stripped. `type user.json | jsonforge types -`.

## Options

| Option | Commands | Description |
| --- | --- | --- |
| `-h, --help` | all | Show help |
| `-v, --version` | — | Show the version |
| `-n, --name <Name>` | types, zod, generate | Root type name |
| `-o, --output <path>` | types, zod, generate | Output file (`generate`: output directory) |
| `-f, --force` | types, zod, generate | Overwrite existing files |
| `-H, --header <"K: V">` | types, zod, generate | Request header for URL input (repeatable) |
| `--timeout <ms>` | types, zod, generate | URL request timeout (default 10000) |
| `--allow-private-network` | types, zod, generate | Allow URLs on localhost / private networks |
| `-p, --port <port>` | mock | Port (default 4000, `0` = random) |
| `--host <host>` | mock | Bind address (default `127.0.0.1`) |
| `--delay <ms>` | mock | Delay every response |
| `-q, --quiet` | all | Print nothing on success (errors are still printed) |
| `--json` | all | Print a machine-readable result or error |

There is no configuration file.

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Runtime error (invalid JSON, file exists, network error, port in use, …) |
| `2` | Usage error (unknown command or option, invalid option value) |

### `--json` output

```json
{ "ok": true, "files": [{ "path": "user.types.ts", "format": "types" }], "warnings": [] }
```

```json
{ "ok": false, "error": { "code": "FILE_EXISTS", "message": "user.types.ts already exists.", "hint": "..." } }
```

## Module format

`jsonforge-cli` is a command-line tool written as native ES modules. It is not meant to be imported as a library and has no public JavaScript API. The **generated** `.ts` files use ES `import`/`export` syntax and work in both ESM and CommonJS TypeScript projects, because your TypeScript compiler or bundler converts them.

## Security considerations

- **URL fetching** only allows `http:` and `https:`. Credentials inside the URL (`https://user:pass@…`) are rejected; use `--header` instead.
- **Private networks are blocked by default.** Requests to loopback (`localhost`, `127.0.0.0/8`, `::1`), private ranges (`10/8`, `172.16/12`, `192.168/16`, `fc00::/7`), link-local (`169.254/16`, including the `169.254.169.254` cloud metadata endpoint, and `fe80::/10`), carrier-grade NAT, multicast and reserved ranges are refused. The check runs on the resolved IP address of every connection, including redirects. Pass `--allow-private-network` to fetch from your own local API.
- **Secrets are not printed.** Header values are never logged. Error messages show only the URL origin and path, not the query string.
- **Downloaded content is never executed.** It is only parsed with `JSON.parse`.
- **No data leaves your machine** other than the request you ask for. Nothing is sent to third-party services.
- **Generated code escapes input.** Property names are emitted as identifiers only when they are valid; otherwise as JSON string literals. Type names are sanitized. Input values are never copied into the generated code.
- **The mock server** binds to `127.0.0.1` by default and prints a warning if you bind to another host. It loads fixtures once into memory and answers requests only from that list, so request paths cannot read other files. Symbolic links in the fixtures directory are skipped.

## Known limitations

- Types are inferred from samples only. A value that is always `null`, an empty array, or an empty object cannot reveal its real type. These cases print a warning and are typed as `null`, `unknown[]`, and `Record<string, unknown>` (`z.null()`, `z.array(z.unknown())`, `z.record(z.string(), z.unknown())`). Edit the output if you know the real type.
- No format detection: dates, emails, UUIDs and integers are plain `string` / `number`.
- No literal or enum inference (`"status": "active"` becomes `string`).
- All objects in the same array are merged into one type; discriminated unions are not detected.
- Structurally identical nested objects under different keys produce separate types.
- Only one input per run. Multiple samples are supported through a top-level array.
- The mock server is read-only, has no `/users/:id` item routes, and does not reload fixtures on change.
- URL responses must have a JSON content type; the response size limit (5 MB) is fixed.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `Invalid JSON in user.json (line 3, column 1)` | JSON does not allow trailing commas, comments, single quotes or unquoted keys. |
| `Unsupported top-level value` | The input must be an object or array. Wrap a single value: `{"value": 42}`. |
| `user.types.ts already exists` | Add `--force` or pick another `--output`. |
| `Refusing to fetch from private or local address` | Add `--allow-private-network` when fetching from your own local API. |
| `Response ... is not JSON` | The server did not send `Content-Type: application/json`. Save the response to a file and pass the file instead. |
| `Port 4000 is already in use` | Stop the other process or use `--port 4001`. |
| `Missing input.` | Pass a file or URL, or pipe JSON and use `-` as the input. |
| `"class" cannot be used as a type name` | `--name` must be a valid identifier that is not a reserved word or built-in type. |
